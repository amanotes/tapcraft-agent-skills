# The `Tapcraft` API

One facade, one import. Game code never calls the old `platform`, `saves`, `AmaGDK`, native bridges, ad/payment SDKs, or `localStorage`.

```ts
import { Tapcraft } from '../tapcraft/index';   // path relative to the script: assets/scripts/x.ts → '../tapcraft/index'
```

`assets/tapcraft/` is the kit's runtime, generated by `npx tapcraft sync` (`npm install` runs it through `postinstall`). Commit it, never edit it: `build`, `check` and `pack` fail when it differs from `tapcraft.lock.json` or the installed kit. The exact public types are `assets/tapcraft/tapcraft-sdk.d.ts`; read them instead of guessing.

## Rules of the API

- **Services** (`lifecycle`, `storage`, `content`, `ads`, `iap`, `analytics`, `profile`, `remoteConfig`, `system`) are always present; **capabilities** (`Tapcraft.caps.haptics`, `caps.audio`) are optional device features. Every module has `available: boolean`.
- Every async call resolves, never rejects. Results are values (`outcome`, `status`, `ok`); `unavailable` and `error` are normal. Do not wrap calls in try/catch for control flow.
- `await Tapcraft.init()` first. Before it resolves, calls answer `unavailable` (subscriptions are kept). `init()` is idempotent and returns `{ ok, host, storage, modules }`; `ok` is true when storage is `ready`.
- The same code runs in the app (`host: 'hub'`), in a plain Cocos preview (`preview`: mock ads, saves in browser storage) and in tests (`test`). Never branch on the host in game code.
- Result unions name every field on every member, so `r.reason` reads without narrowing (the stock Cocos tsconfig has `strictNullChecks` off).
- Keep calls behind small game-owned adapters so tests can use fakes.

## Modules

| Module | Members |
|---|---|
| `Tapcraft.host`, `.game`, `.launch` | host kind; `game` = `{ id, version, build, buildId, channel }`; `launch` = `{ source: explore\|search\|continue\|deeplink\|push\|staging\|dev, payload }`. Known before `init()` |
| `lifecycle` | `firstFrameReady()`, `hidePlatformLoadingScreen()`, `gameReady()`, `gameplayStart()`, `gameplayStop()`, `requestExit()`, `onPause(fn)`, `onResume(fn)`, `onBeforeUnload(fn)`, `onMemoryWarning(fn)`; every `on*` returns an unsubscribe |
| `storage` | `get/set/remove/has/keys/clear`, `getJson/setJson`, `schema`/`setSchema(n)`, `await flush()`, `status`, `bytesUsed`, `limits` |
| `content` | `load/asset/prefetch/pin/unpin/release/has/onLowMemory/trim/url/json/flushCache` ([content-assets.md](content-assets.md)) |
| `ads` | `isSupported(format)`, `isReady(format, placement?)`, `onReadyChange(fn)`, `showInterstitial(placement)`, `showRewarded(placement)` |
| `analytics` | `logEvent(name, params?)`, `setUserProperty`, `progression(status, levelId, params?)`, `resource(...)`, `tutorial(step, status)`; fire-and-forget |
| `system` | `platform`, `locale`, `country`, `deviceTier` (low/mid/high), `safeArea` (points iOS / dp Android), `safeAreaPx`, `audioEnabled` + `onAudioEnabledChange`, `await getServerTime()`, `await openUrl(url)`, `requestReview()` |
| `profile` | `playerId`, `isGuest`, `consent`, `onChange` (2.0: guest only) |
| `remoteConfig` | `getString/getNumber/getBoolean/getJson(key, fallback)` (2.0: always the fallback) |
| `iap` | `getProducts`, `purchase`, `getPendingGrants`, `acknowledge`, `onGrant`, `restore` (2.0: every call `unavailable`) |
| `caps.haptics` | `impact('light'\|'medium'\|'heavy'\|'rigid'\|'soft')`, `notify('success'\|'warning'\|'error')`, `selection()`, `pattern(events)` (≤ 2 s, ≤ 16 events); no-op where unavailable; the app's haptics setting wins |
| `caps.audio` | interface only in 2.0: `available` is false everywhere |

## 2.0 availability

| Surface | State |
|---|---|
| lifecycle, storage, content, ads (interstitial, rewarded), haptics, system, launch | supported in the app |
| analytics | forwarded to the app telemetry when the host has it, else dropped; never depend on it for game logic |
| profile | guest with a per-install id; consent unknown |
| remoteConfig, iap, `caps.audio` | not served: fallbacks / `unavailable`. Do not build features that need them |

Types do not prove a capability is on: check `module.available` and handle `unavailable`.

## Lifecycle

```ts
await Tapcraft.init();
Tapcraft.lifecycle.firstFrameReady();            // first frame drawn
// next frame, once the game's own loading UI is on screen:
Tapcraft.lifecycle.hidePlatformLoadingScreen();
// ...load local core/menu...
Tapcraft.lifecycle.gameReady();                  // menu accepts input

const offPause = Tapcraft.lifecycle.onPause((reason) => app.pause(reason)); // hubMenu | background | ad | exit | system
const offResume = Tapcraft.lifecycle.onResume(() => app.resume());          // call both in onDestroy
Tapcraft.lifecycle.gameplayStart();              // each run; close with gameplayStop()
Tapcraft.lifecycle.requestExit();                // the only way out
```

Without `hidePlatformLoadingScreen()` the app keeps its loading screen until `gameReady()`, at most 20 s. A later boot step sends the earlier ones it implies. Saves are already flushed when pause handlers run. `onBeforeUnload` is synchronous and short (about 150 ms): write what must survive now, never await.

## Storage

- Reads and writes hit memory; dirty keys reach the device 1 s after the first change, on pause, before unload and on `requestExit`. `await Tapcraft.storage.flush()` waits for the native commit (`{ status: 'flushed'|'unavailable'|'error', revision, code }`): call it at milestones (new best score, purchase-like events), not per frame.
- `set`, `setJson`, `remove`, `clear`, `setSchema` return `false` when refused: storage not `ready`, reserved key (`__` prefix), value over 1 MiB, game over 5 MiB (UTF-16 units, keys count). Check `status` before assuming saves exist.
- `storage.status === 'unavailable'`: reads return `null`, writes return `false`, nothing is overwritten. Show the game without progress; never retry-write in a loop.
- `getJson(key, fallback)` returns the fallback when missing or not JSON.
- `schema` is the game's own save-format version (0 = never set): migrate, then `setSchema(n)`. Production saves must stay readable across game updates.
- No cloud sync. Never use `localStorage` or `sys.localStorage` in game code: `check` fails on it. Large levels and replays are content, not saves.

```ts
if (Tapcraft.storage.schema < SAVE_SCHEMA) { migrate(); Tapcraft.storage.setSchema(SAVE_SCHEMA); }
const progress = Tapcraft.storage.getJson<Progress>('progress', { best: 0 });
Tapcraft.storage.setJson('progress', progress);
await Tapcraft.storage.flush();
```

## Ads

- Placements are logical names such as `revive` and `level_end`.
- Rewarded is opt-in. Show the reward before the ad; grant only on `granted`.
- Interstitials only at natural breaks, never before first gameplay or while gameplay is open (`gameplayStop()` first).
- One ad request at a time. Ad calls have no SDK timeout: they settle when the ad closes (the host owns the deadline). If a flow must not wait, race the call against your own timer and keep the UI consistent when the late result arrives.
- Pause gameplay and all audio on pause reason `ad`; resume on `onResume`.
- Do not add a second pacing or capping policy; the platform owns it. `isReady` is a hint for the UI, not a guarantee.

Outcomes: `showRewarded` → `{ outcome: 'granted' | 'cancelled' | 'noFill' | 'unavailable' | 'error' }`; `showInterstitial` → `{ outcome: 'shown' | 'skipped' | 'noFill' | 'unavailable' | 'error' }`. Continue the game on every interstitial outcome.

### Rewarded: revive offer

```ts
import { _decorator, Component, Button } from 'cc';
import { Tapcraft } from '../tapcraft/index';
const { ccclass, property } = _decorator;

@ccclass('ReviveOffer')
export class ReviveOffer extends Component {
    @property(Button) reviveButton: Button | null = null;
    onRevive: () => void = () => {};
    onMessage: (text: string) => void = () => {};
    private busy = false;                                         // one ad request at a time

    async onReviveTap(): Promise<void> {
        if (this.busy) return;
        this.busy = true;
        if (this.reviveButton) this.reviveButton.interactable = false;
        const { outcome } = await Tapcraft.ads.showRewarded('revive'); // settles when the ad closes
        this.busy = false;
        if (!this.node.isValid) return;                           // scene changed meanwhile
        if (this.reviveButton) this.reviveButton.interactable = true;
        if (outcome === 'granted') {
            this.node.active = false;
            this.onRevive();                                      // grant only on 'granted'
            Tapcraft.lifecycle.gameplayStart();                   // reopen the run
        } else if (outcome !== 'cancelled') {
            this.onMessage('No video available right now');       // noFill | unavailable | error
        }
    }
}
```

### Interstitial: natural break

```ts
async function onLevelComplete(level: number): Promise<void> {
    Tapcraft.lifecycle.gameplayStop();                // interstitials are skipped while gameplay is open
    await showResultScreen(level);                    // the player sees the result first
    await Tapcraft.ads.showInterstitial('level_end'); // every outcome continues
    goToNextLevelOrMenu();
}
```

Do not count levels or check `isReady` before an interstitial; the platform paces and caps (`skipped`). Audio and timers stop through `onPause('ad')` and restart in `onResume`, not around the `await`.

### When a flow must not wait

```ts
const timeout = new Promise<'timeout'>((ok) => setTimeout(() => ok('timeout'), 8000));
const r = await Promise.race([Tapcraft.ads.showRewarded('double_coins'), timeout]);
// On 'timeout' continue without the reward; if the late result is 'granted', grant it then.
```

## Testing without the app

- Plain Cocos preview: the `preview` host runs automatically (mock ads close after about 1 s, saves in browser storage). Every app build also serves a test ad during development.
- Unit tests: `await Tapcraft.init({ host: 'test', providers: { ads: TapcraftTesting.fakeAds() } })` swaps any module; `TapcraftTesting.createMockHost({...})` drives pause, ads and storage (`entries`, `rewardedOutcome`, `failStorageLoad`). Fakes record their calls.

## Unavailable capabilities

Do not call native APIs for what the SDK lacks (low-latency audio, purchases, remote config, sharing). When a newer kit marks one available, read its changelog and `tapcraft-sdk.d.ts` first; do not infer behavior from generic SDK documentation.

# Build, check, and device loop

Run commands from the game root. The CLI comes from the project's `com.amanotes.tapcraft-kit` devDependency.

## Runtime sync and kit updates

`assets/tapcraft/` (the `Tapcraft` SDK) is generated by `npx tapcraft sync` from the installed kit and recorded in `assets/tapcraft/tapcraft.lock.json`. `npx tapcraft init` adds `"postinstall": "tapcraft sync"`, so `npm install` keeps it in step. Commit it; never edit it. `build`, `check` and `pack` fail, naming `npx tapcraft sync`, when it differs from the lock or the installed kit (also after `npm install --ignore-scripts`). `npx tapcraft sync --check` only verifies.

Update flow (ask before changing the dependency):

```bash
npm i com.amanotes.tapcraft-kit@latest      # postinstall: tapcraft sync
git add -A assets/tapcraft package.json package-lock.json
npx tapcraft build ios && npx tapcraft check
```

Read the kit `CHANGELOG.md` first. A kit major (engine profile or protocol change) needs a new build and version. Test on a device, `tapcraft pack`, publish a new build and version through the MCP.

## Build

```bash
npx tapcraft build ios
npx tapcraft build android
npx tapcraft build all
```

The kit applies the engine profile, release settings, `md5Cache`, texture presets, and native application hook. Output is `build/<platform>-hub/data/`.

Run `tsc --noEmit` separately when the project has TypeScript. Cocos can otherwise build despite type errors.

## Check

```bash
npx tapcraft check
npx tapcraft check --json
```

Errors block release. Typical errors include:

- `assets/tapcraft/` differs from its lock or the installed kit (`npx tapcraft sync`); a build from another kit (stale `tapcraft.json`: rebuild);
- invalid `game.json`, engine/profile mismatch, or non-kit build;
- kit 1.x leftovers in game sources: `localStorage` / `sys.localStorage`, `AmaGDK`, `__AMA_GDK__`, `vendor/amagdk`, `./hub/*` imports, `jsb.jsbBridgeWrapper`;
- offline start depending on a remote bundle;
- missing bundle config/dependency, scripts in remote content, or compression failure;
- forbidden exit, bridge, path, and hot-update APIs (`game.end`, `jsb.reflection`, `native.bridge`, `setSearchPaths`, …);
- pack over 15 MB, remote bundle over 20 MB, remote file over 2 MB, or total remote over 250 MB;
- debug hosts, localhost/private IPs, or debug flag files in a release.

Warnings require human review: pack over the 8 MB target, remote bundle over 5 MB, large/uncompressed images, large WAV files, metadata, hard-coded CDN hosts, edited `.meta` files of `assets/tapcraft/`, and a game that never calls `Tapcraft.lifecycle.gameReady()` or `hidePlatformLoadingScreen()`.

## Serve

```bash
npx tapcraft serve
```

The server exposes a dev URL and `dev.json` shaped like the CDN. In the internal TapCraft app, set Dev content server to the printed URL. Rebuild and restart the server after content changes.

Plain Cocos Preview runs the SDK's `preview` host (mock ads, saves in browser storage): fine for logic, not a substitute for the app. Unit tests use `Tapcraft.init({ host: 'test', providers: { … } })` ([tapcraft-api.md](tapcraft-api.md)).

## Device checklist

- [ ] Airplane mode reaches menu and first gameplay.
- [ ] Platform loading hides only after the local loading UI draws.
- [ ] `gameReady` fires when menu input works.
- [ ] Remote failure shows placeholder/retry without blocking local play.
- [ ] Gameplay sustains target frame time without decode hitches.
- [ ] Memory returns near baseline after leaving content.
- [ ] Twenty exit/relaunch cycles preserve saves and do not grow memory.
- [ ] Saves survive exit/relaunch (change a value, exit, relaunch); `await Tapcraft.storage.flush()` at milestones; storage `unavailable` does not crash.
- [ ] Background/resume and ads pause gameplay and every audio path.
- [ ] Release logs have no hot-loop spam or uncaught errors.
- [ ] iOS and Android both load the same logical remote bundles.

Preview/editor tests are useful but do not replace this native loop.
